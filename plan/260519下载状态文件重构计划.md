 # Download 状态文件与覆盖确认重构计划

  ## Summary

  - 将 fetch_video_title() 改为 fetch_video_info()，返回完整视频 info 对象；CLI 从 info["title"] 取标题创建/定位 workspace。
  - 保留 info.json 存原始视频信息；新增 status.json 作为唯一下载状态文件，字段包含 stage、status、failed_reason、info_path、last_time、origin。
  - status.json 的写入职责全部收敛到 my_video/core/yt_dlp_download.py；download.py 不再直接更新状态文件。
  - DownloadRequest 保持原样，不新增 status_path / info_path；download() 内部基于 workspace_path 推导 status.json 和 info.json 的约定路径。
  - 当 workspace 已存在且 status.json 为 download/success 时直接跳过；若为 download/running 或 download/failed，先展示上次状态、失败原因、北京时间 last_time，交互确
    认是否覆盖，默认否；非交互环境直接退出，除非显式传 --force。

  ## Key Changes

  - my_video/core/yt_dlp_download.py
      - 新增 fetch_video_info(url, cookie_path=None, proxy=None) -> dict[str, Any]，直接返回 yt-dlp extract_info(..., download=False) 的完整结果。
      - 对 info["title"] 做最小校验；缺失或空字符串时抛错。
      - DownloadRequest 维持现有字段：url、workspace_path、cookie_path、proxy。
      - download() 内部根据 request.workspace_path 推导：
          - status_path = <workspace>/status.json
          - info_path = <workspace>/info.json
          - origin_path = <workspace>/origin
      - download() 在内部负责整个 status.json 生命周期：
          - 开始下载前用 full_update=True 重置状态文件，写入 stage="download"、status="running"、failed_reason=null、info_path、last_time、空的 origin。
          - 每次发现 video_path、subtitle_path、thumbnail_path 后立即增量更新对应 origin 字段，并同步刷新 last_time。
          - 下载成功结束时更新 status="success"、failed_reason=null、last_time。
          - 任意异常时在函数内部更新 status="failed"、failed_reason=str(exc)、last_time，并保留已写入的 origin 字段后再重新抛出。
          - 若最终 video_path 为空，也在函数内部按失败处理后抛错，不再让 CLI 补写状态。
  - my_video/core/workspace.py
      - WorkspaceInfo 新增 status_path: str，info_path 保持指向 info.json。
      - resolve_workspace() 同时生成 info.json 和 status.json 路径。
      - write_workspace_info() 更名为 update_status_for_workspace()，接口改为：
          - update_status_for_workspace(status_path, "key", value)
          - update_status_for_workspace(status_path, {"k": v})
          - update_status_for_workspace(status_path, {"k": v}, full_update=True)
      - 默认行为是增量更新并对嵌套对象做深合并；full_update=True 表示全量覆盖整个状态文件。
      - update_status_for_workspace() 每次写入时自动刷新 last_time，格式固定为北京时间字符串：YYYY-MM-DD HH:MM:SS。
  - my_video/cli/commands/download.py
      - 增加 --force 参数；有该参数时，遇到已有 running/failed workspace 直接覆盖，不询问。
      - 主流程改为：
          - 调 fetch_video_info()，取 info["title"]。
          - resolve_workspace() 后检查 status.json。
          - 若是 download/success，直接输出已有 origin/ 路径并返回成功。
          - 若是 download/running 或 download/failed：
              - 打印上次 status、failed_reason、last_time。
              - 若 --force，继续覆盖。
              - 若是交互终端，询问是否覆盖，默认否；拒绝时退出且不修改任何文件。
              - 若非交互终端且未传 --force，直接退出报错。
          - 允许覆盖时，确保 workspace 存在，清理旧 origin/，并用最新 info 全量覆盖 info.json。
          - 然后调用 download()；CLI 不再写 status.json，只负责展示结果和返回退出码。

  ## Public Interfaces

  - fetch_video_title(...) -> str 删除，替换为 fetch_video_info(...) -> dict[str, Any]
  - DownloadRequest 不变
  - WorkspaceInfo 新增 status_path: str
  - write_workspace_info(...) 删除，替换为：
      - update_status_for_workspace(status_path, key, value, full_update=False) -> None
      - update_status_for_workspace(status_path, mapping, full_update=False) -> None
  - my_video download 新增 --force
  - status.json 固定结构：
      - stage
      - status
      - failed_reason
      - info_path
      - last_time
      - origin.video_path
      - origin.subtitle_path
      - origin.thumbnail_path

  ## Test Plan

  - fetch_video_info() 返回完整 info，并正确透传 cookie/proxy。
  - resolve_workspace() 同时生成 info.json 和 status.json 路径。
  - update_status_for_workspace() 覆盖：
      - 单键更新
      - dict 增量更新
      - origin 深合并
      - full_update=True 全量覆盖
      - 每次写入自动刷新北京时间 last_time
  - download CLI：
      - 首次下载会写 info.json，并由 download() 创建 status.json
      - 已成功 workspace 直接跳过，不调用下载器
      - 已失败或进行中 workspace：
          - 交互确认拒绝时退出且不改文件
          - 交互确认接受时清理旧 origin/ 并重试
          - 非交互且无 --force 时直接退出
          - 带 --force 时直接覆盖
  - yt_dlp_download.download()：
      - 缺字幕/缩略图时不报整体失败，但已拿到的路径应即时写入
      - 视频缺失或其他异常时，在函数内部把状态写成 failed，并保留之前已记录的 origin 字段
      - 不依赖 DownloadRequest 中额外状态字段，完全从 workspace_path 推导状态文件路径

  ## Assumptions

  - info.json 在每次“实际开始下载”前都用最新 fetch_video_info() 结果全量覆盖；跳过场景不重写。
  - last_time 始终由状态写入函数自动维护，使用中国北京时间字符串，不从调用方传入。
  - 覆盖确认文案展示的是 status.json 当前记录的 status、failed_reason、last_time；若某字段缺失则按空值展示，不额外推断。
  - workspace 目录结构约定稳定：info.json、status.json、origin/ 都位于 workspace 根目录下，因此 download() 可安全基于 workspace_path 推导状态文件位置。
